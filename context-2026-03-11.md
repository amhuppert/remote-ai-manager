# Context Window Indicator — Session Context

## Summary

Building a UI component (`ContextFillIndicator`) that displays the percentage of context window filled for a Claude Code conversation. The presentational component is complete with tests and Storybook stories. The data pipeline (extracting token usage from the Agent SDK and wiring it to the component) has not been started yet.

## Key Learnings

### Agent SDK Token Data
- The `@anthropic-ai/claude-agent-sdk` provides `ModelUsage` with `contextWindow` (max tokens) and per-message token counts (`inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`)
- These are available in SDK result/stream messages but are **not yet extracted** into `ConversationState` in CC's data model
- To compute fill percentage: sum all token usage for the conversation, divide by `contextWindow`

### Design System Constraints
- Dark theme with semantic colors: cyan = active/normal, amber = warning, red = danger
- Three-font contract: Display (Anybody), Mono (Geist Mono), Body (Manrope) — the indicator uses Mono exclusively
- Info strip styling: `0.58rem` labels, `0.68rem` container font, `5px` padding, `24px` gap between items
- All values must use CSS custom properties from `:root` — never hardcoded hex/px values
- Glow effects reinforce semantic color meaning via `box-shadow`

### Session Info Strip Structure
- Located in `SessionDetailPage.tsx` lines 1001-1070
- CSS in `globals.css` lines 3040-3172
- Items: Branch, Created, Prompts, Worktree, Conv ID, [Claude Session], Context copy button, TDD toggle
- Each item separated by `<div className="si-sep" />`
- Mobile: collapses to summary view with expand toggle

## Open Questions / Challenges

1. **Token counting granularity**: Should we track cumulative tokens across all messages, or use the latest SDK-reported context window usage? The SDK may report a snapshot per message.
2. **Where to store the data**: Options are (a) add `contextWindowUsage` to `ConversationState` schema, (b) derive from transcript entries on demand, or (c) keep in-memory only via SSE.
3. **Real-time updates**: The component has smooth CSS transitions — should the data update live during streaming, or only after each prompt completes?
4. **Placement decision**: The component is built as a standalone `si-item`. Should it replace the existing "Context" copy button or sit alongside it?
