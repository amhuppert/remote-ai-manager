# Context: Ralph Loop Plan-First Initialization

## Summary

We designed and spec'd a change to how Ralph Loop workflows are initialized in the CC (Command Center) application. The current architecture has the conversation agent pass a single `objective` string to an MCP init tool, which then fires off a separate SDK `query()` call to generate a task plan — losing most of the conversation context in the process. The new design has the conversation agent generate the plan itself and submit both the objective and structured tasks in a single tool call.

All specification phases are complete (requirements, design, tasks). No code has been written yet.

## Key Learnings

- **The information bottleneck is real**: The plan generator (`plan-generator.ts`) reconstructs context by reading the last 6 conversation messages truncated to 500 chars each — roughly 3KB from potentially hundreds of KB of conversation context.
- **The change is surgically scoped**: Only `init-tool.ts` needs modification. The XState machine, iteration execution, API routes, and all downstream systems remain untouched.
- **`createTask()` in `fix-plan-manager.ts` is the canonical factory**: It handles UUID generation, timestamps, and default field values. Both the plan generator and the new init tool should use it.
- **The plan generator is NOT being removed**: It's retained for UI-triggered plan regeneration via `POST /workflow/generate-plan`. Only the automatic `dispatchPlanGeneration()` call from the init tool is removed.
- **The XState machine is created at confirmation time**, not at init time. The init tool writes to `state.json` directly, and the machine picks up `fixPlan` from state when `startWorkflow()` is called later.

## Background Context

### What is CC?
CC (Command Center) is a Next.js 16 web app that manages remote Claude Code coding sessions. Each session runs in an isolated git worktree.

### What is Ralph Loop?
Ralph Loop is an autonomous multi-iteration development engine. It runs Claude Code in a supervised loop — one SDK `query()` per iteration — until an objective completes or a termination condition fires. Key components:
- **Init tool** (`src/lib/ralph-loop/init-tool.ts`): MCP tool that creates the workflow
- **Plan generator** (`src/lib/ralph-loop/plan-generator.ts`): Generates task plans via separate SDK call
- **Orchestrator** (`src/lib/ralph-loop/orchestrator.ts`): Executes individual iterations
- **XState machine** (`src/lib/workflows/ralph-loop/machine.ts`): Manages workflow lifecycle

### Current init flow
1. Conversation agent calls `initialize_ralph_loop` with `{objective: string}`
2. Init tool creates workflow with `fixPlan: []`, `generatingPlan: true`
3. Init tool fires `dispatchPlanGeneration()` (fire-and-forget)
4. Plan generator runs a separate SDK `query()`, generates tasks, persists them
5. User reviews and confirms plan in UI

### New init flow
1. Conversation agent calls `initialize_ralph_loop` with `{objective: string, tasks: [{description, group}]}`
2. Init tool converts tasks via `createTask()`, creates workflow with pre-populated `fixPlan`, `generatingPlan: false`
3. Init tool broadcasts SSE events with task counts and full plan
4. User reviews and confirms plan in UI (no waiting for background generation)

- **Agent plan quality**: Will conversation agents produce plans as good as the dedicated planner? Mitigated by retaining the regeneration endpoint and providing detailed tool descriptions with guidance.
