Managed capability audit — 22 September 2026

Inspected revision `fa2de91e71cd213f13ee00d68e6c407b5dfeceb2`. Installed baselines: Claude Agent SDK 0.3.257, Codex/SDK 0.153.3, Cursor SDK 1.0.31. This is an audit of conversation delivery, including subsequent turns. No production implementation or live capability configuration was changed.

CC has the four-layer override machinery, but it does **not** currently guarantee that every disabled capability is unavailable. The most serious issues are Claude’s ineffective permission callback, Claude MCP updates that never reach a reused runtime, and discovery that disagrees with native capability identities/defaults.

**What the configuration controls**

Skills/plugins/agents use backend-specific cascades. The narrowest explicit override wins: global → project → session → conversation; resetting an override falls back to its ancestor/native default. A disabled plugin forces discovered child skills/agents off while preserving their own override. Project conversations correctly skip the session layer for these cascades. See [resolver](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-capabilities/resolver.ts:183), [runtime composition](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-capabilities/runtime-composer.ts:187), and [scope reads](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-capabilities/default-deps.ts:189).

MCP definitions come from CC’s global MCP file and the active checkout’s root `.mcp.json`, with project definitions replacing same-key global definitions. Enable flags and per-tool overrides then use the same four precedence levels for session conversations. Per-tool overrides are field-wise patches: enabling one tool removes its deny; it does not unexpectedly make that tool the only allowed one. See [definition sources](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/mcp/discovery-command-center.ts:64), [MCP cascade](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/mcp/resolver.ts:94), and [tool policy merge](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/mcp/policy-resolution.ts:17). Transient workflow tooling is merged last and can replace a same-ID configured entry; it is an additional host-owned input, not a fifth operator override layer.

CC’s own bundled skills are deliberately host capabilities, outside user overrides. They remain attached even when user skills/plugins are disabled. This is an explicit repository contract, not a broken toggle. Native provider settings and CC override levels are also different concepts: for example, a Claude project settings file can affect the native baseline underneath CC’s global/project/session/conversation cascade.

**Inherent limitations of the current backend/API surface**

A. **Claude: native per-skill overrides exclude plugin-owned skills.** Anthropic explicitly states that `skillOverrides` does not apply to plugin skills; the installed implementation checks plugin source before reading overrides. Disabling the entire parent plugin works through plugin controls, but the current native skill setting cannot disable one plugin child. CC additionally needs to mark these individual toggles unsupported or adopt a different delivery strategy. This is separate from the fixable discovery and permission bugs above. Evidence: [Anthropic skill overrides](https://code.claude.com/docs/en/settings-reference#skilloverrides), [CC currently emits them anyway](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-backends/claude/runtime-config/translator.ts:80).

B. **Codex: no legacy SSE MCP transport; native plugin catalog APIs are not yet production-ready.** Current official app-server documentation also marks `plugin/list` and `plugin/read` as under development and unsuitable for production clients. This constrains discovery implementation choices, but does not justify incorrect filesystem discovery. Native per-tool filtering is available for stdio and Streamable HTTP, but the current Codex MCP transport schema does not accept legacy SSE. A bridge/protocol adapter would be CC work; direct native transport parity is unavailable. The compatibility metadata correctly identifies this. Evidence: [transport declaration](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/mcp/backend-capabilities.ts:142), [Codex MCP](https://developers.openai.com/codex/mcp).

C. **Cursor: no selective native skill/plugin attachment API.** The SDK exposes ambient setting-source switches, explicit agents and inline MCP, but no selected native skill/plugin roots. CC uses `settingSources: []` and a selected prompt catalog. Consequently native plugin hooks/rules/commands and some skill execution controls do not have full native parity. Importing supported components, including MCP, is still possible and belongs to CC work; the absence of a selective native plugin attachment API should not excuse those omissions. Evidence: [ambient isolation](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-backends/cursor/policy.ts:38), [catalog delivery](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/agent-backends/cursor/capability-delivery.ts:59), [SDK options](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/node_modules/@cursor/sdk/dist/esm/options.d.ts:150).

D. **Cursor: provider administrative controls and curated built-in subagents remain outside CC’s full authority.** The SDK’s inline MCP path still respects provider admin policy; there is no public bypass. Its main-loop tool/disallowed-tool controls do not fully define native subagent toolsets. Therefore enabling a CC tool does not guarantee provider policy permits it, and custom-agent toggles are not an exhaustive switchboard for every built-in agent type. CC’s bridge still enforces its tool restrictions for requests through the managed endpoints. The `strictAuthoritativeConfig=false` declaration is appropriate. Evidence: [honest authority metadata](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/src/lib/mcp/backend-capabilities.ts:167), [main-loop tool scope](/Users/alex/github/command-center/.worktrees/cursor-skills-plugins-mcp-744001/node_modules/@cursor/sdk/dist/esm/options.d.ts:330).

Cursor skills/plugins/agents being frozen until a new conversation, and Claude agent updates being declared next-conversation, are current CC application policies. They are not proven inherent provider immutability constraints. The user-facing timing should remain explicit; faster application can be implemented deliberately.
