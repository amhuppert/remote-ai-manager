Problem

A graph workflow execution context produces no machine-readable output. The implementer turn is deliberately free-form (implementer-runner.ts passes no outputFormat, to preserve the streaming markdown turn body), context state carries no output field, and the only cross-context channels are git reachability (lane-readiness.ts) and prose shared documents. A downstream context learns about upstream results only by reading merged code or shared-document prose; nothing can branch on, filter, or aggregate a typed upstream result.

This is the missing data plane for the workflow vision's patterns: Classify-And-Act, Generate-And-Filter, and Tournament verdicts all require a context to emit a typed result that downstream machinery consumes (roadmap D2), and D4's conditional edges have no value to condition on until it exists.

Meanwhile the structured-output machinery already exists and is unused by contexts: the AgentCall facade gate is opt-in on request.outputSchema with candidate-extraction fall-through (native → raw JSON → fenced) and a bounded repair turn, and the graph validator already runs schema-validated task runs through the shared chain. But every current producer passes a compile-time literal schema — no author-supplied schema is plumbed anywhere in the system.

Outcomes

A workflow author can declare an optional outputSchema (a JSON Schema object) on any execution context — at planning time, in the builder, or later through the doc 05/06 edit surfaces. When such a context finishes its work, exactly one validated output conforming to that schema exists: validated through the existing structured-output gate chain, persisted durably on the execution, and surviving server restart.

Downstream contexts see upstream structured outputs injected into their iteration prompts in a documented format, and engine code can read any context's output through a typed accessor — the seam D4 conditional edges will later consume. Contexts without an outputSchema behave exactly as today: free-form streaming implementer turns, no schema, no gate.

Non-goals

›Conditional edges or any engine branching on outputs — that is D4; this deliverable only provides the data plane it reads.
›Specialist validators and implementor personas (D3).
›Extending the hand-rolled JSON-Schema subset validator to full JSON Schema — $ref, anyOf, allOf, format stay unsupported; authoring-time validation enforces the supported subset instead.
›A workflow- or global-tier default outputSchema in the config cascade — a shared default output shape across heterogeneous contexts is meaningless; the field is per-context only.
