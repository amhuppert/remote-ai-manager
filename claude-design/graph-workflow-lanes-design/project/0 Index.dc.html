Context node — every state

One component, one anatomy: title and status · lane chip, this context's grade, and its owned paths · the crew ledger (implementer, then each validator seat with its authority) · progress · a footer that carries iteration and loop pass. A cyan dot marks a value set on this context; the reason is in the node's accessible name, so it is not hover-only. A lane never carries a grade — every grade you see belongs to the context showing it.

completed · full grade
pending · waiting for the lane
read-only · session lane
halted · resumable
awaiting context approval
draft · builder
published · derived UI state

Published is derived. It is shown after publication so the canvas can say what happened, and it is never treated as a stored context status — the stored statuses are the engine's, and the node's other seven states are those.

What an implementer must not re-decide

  • A lane has no grade. Grade, and owned paths, belong to the context. Lane headers show status, membership and a grade summary only.
  • Crossing a lane during a drag writes placement.lane and nothing else; grade and paths carry across verbatim; invalid drops are refused without mutating the draft.
  • An empty lane is client-only, never serialized, and does not make the definition dirty.
  • The cascade is Global → Workflow → Context at three granularities — block, role (agent validation), field (collaboration, lane-merge validation). Reset clears at that same granularity; Reset all clears the tier, it does not restore a fixture.
  • Live configuration is context-oriented and snapshot-based, in one of four modes: editable, pause-to-edit, frozen, read-only.
  • Current versus History is the execution lease, not terminality.
  • Approval, lane join and publication are three different things, and definition approval is a fourth.
  • Conversation is the durable history row; iterations are events inside it.

Out of scope

  • Backend, engine, schema or persistence changes.
  • A persistent lane entity.
  • Generic live Workflow-default editing.
  • A builder Launch action, and any new launch behaviour.
  • New validator de-duplication behaviour — rendering and ownership are unchanged.
  • New approval or join semantics.
  • New authoring for graph fields that are not authorable today.
  • Unrelated existing product bugs.

Design-system notes

The 420px rail is the one approved exception to the 340px standard (470px for the standalone component study). Everything else follows the system: Geist Mono for interface text and Manrope for conversation prose, 0.7rem minimum, token colours and spacing, 4/6/10px and pill radii, canonical SVG icons with no Unicode glyph used as an icon, violet reserved for Codex, pulse only on live status, reduced-motion honoured, and every interactive element a real focusable control.
