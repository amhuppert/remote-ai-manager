What is live
Root is a pure read-out; the four group screens carry the editing. Switches flip, value chips cycle their options, and any value that stops matching its inherited one flips to set here — cyan edge stripe, ↺ reset, and a helper line naming the value it replaced. Turning an inherited gate off reads as Disabled, red edge, with its cohort kept underneath (expand the caret on Context validator).
Rarely-used settings sit under Advanced on each screen and are hidden until asked for — except when overridden, in which case they are pulled up automatically so nothing deviating can hide. Group cards and the header count recompute from the same state.

Two-level panel, like OS settings. The root screen is a pure read-out — four cards, one line per setting, override dots inline — so scanning never fights with editing affordances. Clicking a card pushes a group screen where the full InspectorConfigBlock editors live (existing component, unchanged). Rarely-used settings cost one line on the root instead of a whole block. Trade-off: two clicks to edit.

The IDE-settings pattern: every setting is one row with its control inline — no disclosure needed for the common cases. A curated Common filter is the default (≈8 rows); Modified shows only deviations; All is the escape hatch, searchable. Provenance is an edge stripe + tier tag instead of a badge row, and editing an inherited row silently promotes it to a context override (helper line under the hovered row).

The workflow tab's job is different from the context tab's: "what does a new context get, and which contexts deviate". Each default carries a ↳ N ctx chip; expanding it (shown on Implementer) lists the deviating contexts with their values — click-through selects that context. Workflow-only settings (lane-merge, launch params, charter) get their own group so they stop reading like cascade rows. Pairs with any of 1a–1d.
