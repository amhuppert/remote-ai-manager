Why conversations, not rounds
An iteration can span several conversations (context-limit rotation) and a conversation can span several iterations (a failed validation returning to the same implementer). So the durable row is the conversation — the thing a transcript belongs to — and iteration boundaries, task completions, validator verdicts and rotations are events plotted inside it. Every row keeps its Transcript button forever; rotations cross-link rows (↺ from conv_… / superseded by conv_…). This panel is what the Conversations group in 1b opens into.
Graph Workflow — lanes as a first-class axis
Placement is already the engine's only lane authority — every context declares placement: { lane, mode }, lanes become branches and worktrees, and joins merge them. The proposal makes that visible: the canvas becomes horizontal swimlanes (one band per lane, flow left→right), joins render as converging chevrons, and the node is redesigned to carry its full config at a glance. Both side panels collapse. 1a is the pixel-faithful recreation of today's page for comparison.
