How it is reached
The rail has one stack. Selecting a node shows the run inspector (status, lane, latest validation, conversations); its Config card pushes this panel onto the same rail, so the header keeps a ◂ Inspector return instead of opening a second surface. Collapsing the rail with ▤ Inspector collapses whichever level is showing.
Editing a live run
Nothing is greyed out — the config a running context reads is re-resolved at each iteration boundary, so an edit is written now and takes effect on the next iteration; the amber strip says exactly that. On Workflow scope the same strip narrows the promise: defaults reach contexts that have not started, and started contexts keep what they were dispatched with.
Node ↔ panel
The Δ marks on the node are the node-side view of the same cascade the panel reports as a cyan edge and ↺: here the validator cohort is switched off on this context, which the node shows as cohort off and the panel as 1 off here.

One rail, no modal
The builder's config is not a dialog behind a node — it is the permanent right rail, so authoring the graph and authoring its config are the same session. The scope switch is the selection: nothing selected means Workflow (charter, launch parameters, and the defaults every context inherits); selecting a node flips it to Context and the same drill-down opens on that context, with W tags on everything still inherited.
What the builder adds
Two blocks only exist here: the Charter (invariants and ranked sources of truth, scoped per context) and Launch parameters, which is what the Launch… dialog collects. Lane-merge validation also stays workflow-only — contexts cannot override it, so it appears under Quality gates on this scope alone.
Draft, not live
No amber strip: everything is a draft edit against rev 5 and lands on Save, and the topbar owns Validate / Save / Launch. The panel footer keeps the same provenance legend and reset all in both hosts.
1a Inspector — every real config option, grouped and drilled the panel on its own, both scopes, all eleven cascading blocks
Grouping
Context scope: Brief (title, description, acceptance criteria, output schema, upstream inputs) · Placement (lane, write grade, owned paths) · Agents · Quality gates · Execution policy · Tasks. Workflow scope swaps Brief/Placement/Tasks for Charter and Launch parameters, and gains lane-merge validation — the one block contexts cannot override.
Depth
A block whose editor is more than three fields becomes its own screen: implementer, collaboration, the validator cohort (and one screen per seat, with authority, strategy, instructions, runtime and continuity), script validator, agent validation, lane-merge, plan repair, each task, the output schema. Everything shallower stays inline on its group screen, so no screen is longer than a scroll.
Provenance
Each cascading block resolves per tier and reports it: G/W tag for inherited, cyan edge and ↺ for set-here, red for a gate switched off here. Editing an inherited block promotes it — a copy of the resolved value lands in this tier, which is what the real onOverride does. Nothing is hidden behind a disclosure: each drill-in shows every setting it owns, split into section cards.
