Reused

The row list is the Tasks list geometry (numbered gutter → title → right-aligned meta) with the number swapped for a declared/undeclared glyph. Field names use the same inline <code> chip as GATE_CODE_CLASS. The scope picker is a plain Select, same as ImplementerEditor's model pickers.

Swappable list source

The component takes inputs: Array<{contextId, title, hops, fields | null}> and renders exactly that — it never walks the graph itself. Whether the resolver returns direct predecessors or the full transitive set is a caller decision, and the hops value is what drives the direct / 2 hops label. If the engine settles on direct-only, drop the selector and the component is unchanged.

New

Listing upstream contexts that declare no schema, greyed. Omitting them would be tidier but wrong: an author looking at an empty list can't tell "no upstream" from "upstream produces nothing structured", and the second is a fixable authoring mistake. The row is also the natural place to offer declare a schema there.

Friction

The builder inspector's context tab has no read-only-reference section today — everything in it is editable — so this is the first block that is purely informational, and it reads slightly like a dead control. Giving each row a click-to-select-that-context affordance (the graph already supports selection) would fix that, but it means the inspector's context tab starts navigating, which it currently never does. Worth a decision. Second, smaller: the field-name chips truncate badly for a wide schema at 390px, and there is no established "+N more" affordance in CC to fall back on.
