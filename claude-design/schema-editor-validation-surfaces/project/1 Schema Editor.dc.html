Reused

The label + inline-action row, hint line, and FieldError red-text pattern come straight from the acceptance-criteria field. Input chrome is the existing WB_TASK_INPUT recipe (4px radius, border-default, cyan focus border + glow). The shape chip is the StatusChip neutral pill. Empty state is the dashed ghost box already used by + Add Task and the node's none validator pill.

New

Three things CC has no precedent for: (1) a line-number gutter — a monospace code field where errors cite line/column needs it; (2) a path-keyed error list — a mono path chip plus prose, distinct from the single-line FieldError; (3) a cleared notice with Undo, because clearing a schema silently changes every downstream context's prompt.

Suggested primitive

ui/CodeField — gutter + monospace textarea + a issues[] slot rendering {path, message, tone}. Second consumer already exists: ParameterDeclarationEditor's enum-options field, and any future preMergeCommand editor.

Friction

FormField assumes one message, one tone — it can't carry an ordered issue list, so this field bypasses it. And CC has no error tone below "blocked": format is ignored by the backend rather than fatal, which really wants amber, but amber is reserved for awaiting — so it renders red here. Worth a decision in the spec.
