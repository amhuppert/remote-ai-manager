Reused

Everything. One new GraphWorkflowHaltReason variant — output_schema_validation — with a headline / detail / action case in the formatter, and the status bar, ContextHaltCard, HaltDetailsDialog, and event log all render it with no changes. The issue list is the existing haltPathsClass recipe that merge_precondition_failed already uses for dirty paths — an amber <code> locator followed by prose. Circuit-breaker and iteration state stay in their own sections; the halt does not restate them.

How it reads as different

Three signals, no new colour: (1) a kind badge in the validation-card badge row — Output schema where an agent validator says Context; (2) issue titles are instance paths (/verdict), never prose; (3) the dialog shows rejected value beside declared schema — a diff no agent-validator failure has. Same red chrome, because the consequence is identical: the context did not complete.

New

One action: Edit schema in the dialog's DialogActions, beside Resume. Resuming into the same too-tight contract just burns the iteration; this is the same shape as the existing Open the merge gate → deep link on the delivery-gate halt.

Friction

ValidationCard's badge row derives its lane badge from sessionRef.lane via getLaneBadgeLabel, which only knows context_validator. A schema rejection has no lane at all — it is engine-side, not an agent turn — so the card needs a kind field of its own rather than another lane value, and View Transcript must be absent (there is no conversation to open). Second: GraphWorkflowValidationResultEvent.issues is {title, description} prose — carrying a machine path means either abusing title as a path string (done here) or widening the event with an optional path. The widening is the honest fix.
