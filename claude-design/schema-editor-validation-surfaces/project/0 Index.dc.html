Structured output for execution contexts

Six prototyped surfaces for context-structured-output (roadmap D2). Each file carries its own state switcher, a 390px mobile column beside the desktop frame, and a collapsible rationale note. Nothing assumes how the output is produced — only that a context declares a schema and eventually has a validated output or a rejection.

1 Schema editor

The shared field. Raw JSON, line gutter, path-keyed subset errors. Empty · valid · invalid JSON · unsupported keyword · cleared.
2 Builder inspector

In the Brief group as identity content — no provenance badge, no cascade chrome. Set · edit · clear, with the save gate.
3 Live config tab

Seven affordances: editable, dirty, invalid, pause-to-edit, frozen, execution read-only, revision conflict.
4 Captured output

Collapsible tree, copy, parse-source and repair provenance. Plus three graph-node indicator candidates on real nodes.
5 Validation failure

Halt bar → context halt card → details dialog → History entry, and how it reads apart from a task validation failure.
6 Upstream inputs

Read-only list of what this context's prompt will receive, with a swappable scope source.
Decisions the spec still owes
  • format is ignored rather than fatal — it renders red like a hard error because CC has no tone between "fine" and "blocked". Amber is reserved for awaiting.
  • contextOverrideCount must exclude the schema, or the resolved-setup strip's override count goes wrong.
  • ValidationCard needs a kind discriminator, not another lane value — a schema rejection is engine-side and has no transcript to link.
  • ValidationResultEvent.issues is prose-shaped; carrying an instance path needs an optional path field.
  • Two primitives would earn their keep: ui/CodeField (gutter + issue list) and ui/JsonTree (fold + copy). Both already have second consumers.
  • The frozen-config banner uses a 🔒 emoji, which the design system forbids. Inherited as-is; worth replacing while this area is open.
