Reused

All four affordance banners are the existing ones, unchanged — frozen, read-only, pause-to-edit (amber), and the revision_conflict notice. The field lands inside the existing Context ConfigBlock, so it inherits readOnly from the same resolveAffordance result every other control uses. The sticky save bar and its Saving… label are untouched.

New

Two additions. (1) A read-only explanation under the field: the shared banner says "frozen", but an operator looking at a schema needs to know the output is already captured and re-reading it won't change anything — so the field states that itself. (2) A Runtime row for the output, alongside Isolation / Worktree / Branch: it's runtime fact, and the row grid already exists.

Spec notes

The flat ConfigDraft takes outputSchema: string (the raw text, not the parsed object) so the diff is a plain string compare and a half-typed schema survives an SSE rebase. diffToUpdateContextOp parses on submit and emits outputSchema: object | null; threeWay then works unmodified because the field is a scalar.

Friction

Three things fought back. (1) The save bar is enabled purely by dirty; there is no notion of a draft that is dirty but invalid, so a client-side validity gate has to be threaded into the disabled condition. (2) rebaseDraft's three-way merge on a free-text field means a concurrent schema edit silently keeps yours — acceptable, but it should be called out to the user, and there is no per-field conflict affordance to do that with. (3) The frozen banner uses a 🔒 emoji, which the design system forbids — inherited as-is here, but worth replacing with an SVG lock while this area is open.
