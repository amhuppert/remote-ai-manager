Notepad: the calls I made, and why
Seven pages cover the surface. Everything below §6 of the brief was mine to decide; here is each decision and what I rejected. Review decisions are settled. This bundle ships alongside the approved spec: the spec owns the data model, protocol, event vocabulary, XML forms and CLI — these pages own how the UI looks and behaves.

Decisions
Where it lives: sixth tab, list → open
Notepad is a sixth right-pane tab. Inside it, the Docs pattern: a browse list opens one notepad, a back chevron returns, list state survives. One notepad open per pane — the working-set machinery (tabs inside the pane) is ceremony this slice doesn’t need; the list is one click away. Rejected: a dedicated page (breaks R14’s side-by-side contract), a floating window (CC has no floating-window vocabulary), multiple simultaneously open notepads.
Editor / preview: stacked, both live, three postures
Editor above, rendered preview below, a WRITE / SPLIT / READ segmented control. Stacking keeps both at full pane width — a vertical pane sharing the screen cannot afford to halve its line length. Rejected: side-by-side (line length), edit-vs-rendered swap (the ticket editor’s pattern, explicitly not R5.2), and WYSIWYG — I agree with the brief’s baseline: a Markdown→doc→Markdown round-trip that corrupts one agent-authored construct costs more than literal Markdown ever will with this audience.
Scope legibility: structure first, glyphs second, never color-coding
In the list, scope is structural — PROJECT and GLOBAL sections, project first because it’s the local context. Everywhere else a glyph carries it: page for project, globe for global, plus a quiet pill in the open header, a meta cell in the picker, and a small “global” suffix inside chips. Scope never gets an accent color; accents are semantic in CC and scope is not a status.
Identity: Notepad claims blue
Picker glyphs are kind-colored (conversations cyan, tickets amber, specs violet). Notepad needs an identity or it disappears among ten kinds. Blue is the one accent the system reserves “rarely used” with no semantic load; every alternative lies (green = success, amber = awaiting, violet = Codex). Approved in review — blue is Notepad’s.
Organization without search
Pins are the working set and always surface first. Scope sections cut the field in half; recency is the default order, name sort for known targets; archive collapses dead weight behind a count. Forty notepads is ~2.5 screens of 33px rows — scannable. “I know its name” is already served by the picker’s type-to-filter, which is not full-text search and stays within the exclusion.
Write mode: quiet by default, loud only when it bites
A chip in the open header reads “agents: full edit” in tertiary — present, not shouting. Only read only gets the amber lock treatment: it is the exception state, the one you set deliberately. Append-only marks the surface with an end-of-document rail (“agents append below this line”) so the guarantee is visible where it acts. The mode menu explains each option in one line and ends with the sentence that matters: governs agents only — you can always edit. Non-default modes also surface as a small lock in list and picker rows. Full edit is the default in both scopes — per-notepad tightening plus history/restore is the mechanism.
Attribution: revision-grain, honestly
Revisions are full snapshots, so authorship exists at revision grain — the UI never pretends finer. There is no presence signal: the app learns about agent activity only when a write lands, so the first agent-visible moment is the landed draft (“claude wrote rev 13”). New lines carry the author’s rail (cyan agent, amber you) with a rev tag, and the meta line re-attributes (“rev 13 · claude · just now”).
The collision: a banner, not a dialog
When an external write lands on a dirty buffer: one amber strip — “claude wrote rev 14 while you were editing. Your draft is untouched and will save as the new head.” Actions: Review rev 14 (opens history) or Dismiss. It never blocks typing, never offers a merge (merging is explicitly out of scope), and resolves itself into a quiet green note when your autosave flushes. The user’s buffer is sacred; the machinery already guarantees it — the banner’s only job is to say so.
History: restore needs a diff
List (author dot, origin conversation, time, head badge) → snapshot preview → two diffs — what a revision changed (vs previous) and what restoring it would change (vs current) → restore. Every diff affordance routes here: “View diff” on a landed draft opens this panel — one destination, one presentation. Restore is immediate, no confirm dialog; the button carries the contract: “copies this snapshot forward as rev N+1; nothing behind it changes.”
The chip: qualitative weight, no numbers
The prompt chip is name + scope. Its hover peek answers “what am I handing over?”: revision, freshness, write mode, a two-line content preview, and counts of embedded refs — plus the delivery contract in one sentence. No character or token figures; the cost estimate is deferred and half-numbers would anchor wrong.
Settled in review
Write-mode default: full edit stays, both scopes
The global-read-only recommendation was considered and declined. Per-notepad tightening plus history/restore is the mechanism; the agents: full edit default presentation is unchanged.
History diff: in scope
The snapshot / vs-previous / vs-current design ships in slice 1. “View diff” on a landed draft (04) and the history panel (05) are one destination, one presentation.
Mobile: in scope
On ≤768px the notepad joins the mobile bottom bar as a full-screen panel — browse, open, read, and the write-mode control. No Markdown-with-chips editing surface on mobile this slice; quick capture stays deferred. Designed in 07.
Restore stays immediate
No confirm dialog. The restore button carries the contract: a restore is a new head, never a rewrite.
Remaining flags
R14’s 340px legacy width can’t hold SPLIT
In the 50/50 split layout the pane is comfortable. At the legacy 340px right-pane width, editor-plus-preview stacked still works but each half is a slot, not a surface. The design degrades deliberately: below ~420px the pane opens in WRITE with the preview one tap away, rather than pretending SPLIT is usable. Shown as the “narrow” tweak in 01.
Small flags
Archived notepads should be reachable in the picker behind the existing Alt+A idiom, matching conversations. The picker group answers to “notepad”/“notepads” aliases; the trigger is whatever the picker already uses — unspecified here.
Prototypes are design artifacts against the CC design system (tokens, chip grammar, picker anatomy read from source). A coding agent re-implements in React; visual + interaction intent is the contract.
