## Implementation Notes

- Harness (`assertRoundTripDurability`, `src/lib/shared/testing/round-trip-durability.ts`) enforces a recursive completeness guard BEFORE persist: every introspectable persisted key path must be non-default in the maximal fixture or declared in `fieldPolicies`; arrays need >=1 fully-populated element, records >=1 entry. For symmetric repos `persist()` returns the fixture as `expected`; for generated-value paths declare `derived-on-write` and have `persist()` return the actually-stored value. Reload `null` is a failure.
- Minimize `not-persisted` declarations — each is a reviewed claim. Verify against the table DDL (`state-db.ts`), the repo write bind, and the read mapping that the field truly has no column/bind/read. A field that SHOULD persist but doesn't is a pendingQueue-class production gap → report it, don't hide it in `fieldPolicies`.
- 2.1 conversations: only `activeTurnSource` is `not-persisted` (transient XState-derived runtime state, no `active_turn_source` column). Repo is symmetric (no write-derived fields).
- 3.4 sweep ledger — MIGRATED (round-trip fakes): collaboration `deps-factory.test.ts` (markConversationAwaiting → reload status/unread/pendingQuestionId/pendingQuestions), collaboration `route-handlers.test.ts` (START metadata → reload transcriptPath/status/promptCount). LEFT on lightweight stubs (stub-only, fixed-input, no mutate→read-back, Req 3.4): `actor-implementations.test.ts` (capture-stubs asserting the mutator was called), `prompt/{queue-route,sdk-driver,route-handlers}.test.ts`, `conversations/messages-route.test.ts`, `workflow-graph/{workflow-continuity-service,validator-runner,execution-route-handlers}.test.ts`.
