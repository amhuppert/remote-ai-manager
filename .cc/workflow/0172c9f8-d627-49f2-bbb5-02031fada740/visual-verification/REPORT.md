- `remediate-peek-auq-resolution-refresh`: AUQ answer clears in the API but the open peek and sidebar row stay stale.

## Final wiring review

- `src/features/session/sidebar/PeekPopover.tsx`, `src/features/session/sidebar/use-peek-reply.ts`, and `src/features/session/sidebar/ConversationSidebar.tsx` do not import or reference `useSendPrompt`.
- The peek reply path posts through `usePeekReply`/`createPeekReplySubmitter` and does not import or mutate the session-detail Zustand store. The peek AUQ path calls `useAnswerQuestionMutation`; that mutation invalidates React Query caches but does not write to the session-detail Zustand store. `ConversationSidebar.tsx` imports session-detail store hooks only for sidebar UI state (collapsed/filter/session filter), not peek conversation state.
- Row data passed to `<PeekPopover>` comes from `useActiveConversationsQuery()` via `activeConvoList`, `renderRow`, and `peekConversation`. The only separate query in the peek path is `useConversationMessagesQuery(...)` for transcript messages, not duplicate row data.
- The existing `src/components/AskQuestionPanel.tsx` component is reused directly by `PeekPopover.tsx`. Grep found no new implementation of the AUQ option/Other UI outside the existing component, its CSS, stories, and tests.
- `pendingQuestionId` and `pendingQuestions` flow from `src/lib/conversations/schemas.ts` and the state-store conversation mapping into `src/lib/active-conversations/schemas.ts`, through `derivePendingQuestionFields(...)` in `src/lib/active-conversations/route-handlers.ts`, then through `useActiveConversationsQuery()` row data into `ConversationSidebar.tsx` and `<PeekPopover>`. No consumer re-derives the structured AUQ payload from a separate source.
